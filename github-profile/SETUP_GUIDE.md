# GitHub Setup Guide

A quick guide to get your profile and projects live on GitHub.

---

## 1. Set Up Your Profile README

Your GitHub profile (github.com/v77vv) can show a custom page to anyone who visits it.

**Steps:**
1. Go to github.com and click the **+** icon → **New repository**
2. Name the repository exactly: `v77vv` (same as your username)
3. Check **"Add a README file"** and make it **Public**
4. Click **Create repository**
5. Copy the contents of `github-profile/README.md` into the README editor
6. Click **Commit changes**

Your profile page will now show your custom README.

---

## 2. Start a New Project from a Template

When you want to start a new project, pick the right template folder:

| Project type | Template folder |
|---|---|
| AI / Claude API | `project-templates/ai-project/` |
| Molecular dynamics | `project-templates/molecular-dynamics/` |
| Fun / misc | `project-templates/fun-project/` |

**Steps:**
1. Create a new repository on GitHub (github.com → **+** → **New repository**)
2. Give it a clear name like `protein-folding-study` or `claude-summarizer`
3. Copy the template folder contents into your new repo
4. Fill in the `README.md` with your actual project details
5. Start building!

---

## 3. Add Topics to Your Repositories

Topics are tags that help people find your projects.

**For AI projects:** `python`, `ai`, `llm`, `claude`, `anthropic`
**For molecular dynamics:** `python`, `molecular-dynamics`, `openmm`, `biophysics`, `simulation`
**For fun projects:** `python`, `arduino`, `hardware`, `maker` (whatever fits)

**How to add topics:**
1. Open your repository on GitHub
2. Click the gear icon next to "About" on the right side
3. Type topics into the "Topics" field
4. Click **Save changes**

---

## 4. Recommended Repo Naming Style

Use lowercase with hyphens. Examples:
- `protein-folding-alanine`
- `claude-recipe-generator`
- `led-music-visualizer`

---

## Tips for Non-Coders

- **Commit often** — even small saves are good. Think of it like "Ctrl+S for your whole project."
- **Write READMEs first** — describe what you're building before you build it. It helps clarify your thinking.
- **Public repos are your portfolio** — make them readable and well-described.
